# RecallCode 2.0

免登录、离线优先的 Manifest V3 插件；Side Panel、Dashboard 和力扣页面共用本机数据，不依赖 Python 服务。

验收计划：`../docs/RECALLCODE_V2_PLAN.md`。仓库审计及阶段实际状态：`../docs/RECALLCODE_V2_AUDIT.md`。

## 安装

1. 解压 `recallcode-v2.zip`，或直接使用 `extension/dist/`。
2. Chrome 打开 `chrome://extensions`，开启开发者模式。
3. 点击“加载已解压的扩展程序”，选择包含 `manifest.json` 的目录。
4. 固定并点击 RecallCode 工具栏图标，打开侧栏；底部“打开完整管理页”进入 Dashboard。
5. 按三步引导选择题单、历史状态和预算。可不选预置题单，随后导入自定义题单。

构建目标 Chrome 桌面 114+，实际测试 Chrome for Testing 156.0.8078.4。原生授权弹窗、物理工具栏点击与最低版本 Chrome 仍待人工复核。

## 构建和测试

需要 Node.js >=24（实际使用 v26.1.0）。在本目录运行：

```sh
npm ci
npm run test
npm run build
```

`dist/` 可直接加载。`npm run dev` 仅供界面开发，访问 `/dashboard.html`；Chrome API、后台和权限功能须加载构建测试。修改后在扩展管理页重新加载，并刷新旧力扣标签。升级前先备份，尽量保持相同加载目录和扩展 ID。

真实浏览器测试：

```sh
npx playwright install chromium
npm run test:browser
```

测试采用独立浏览器配置，只在 `test-results/e2e/extension` 测试副本中预授予中国站权限；正式 `dist/manifest.json` 保持可选权限。没有 mock 力扣页面或业务 API。不要将测试副本作为正式安装包。访问公开页面需要联网，另有断网训练与保存验证。

## 日常使用

- **今日**：按预算混合新题、历史初评、到期复习。暂缓仅影响当天，不改变 FSRS。完成任务占用计划预算，避免无限补题；统计仍仅累计真实秒数。
- **题库**：完整 100/150/50；搜索及题单/状态/难度/分类筛选；批量标记历史做过；改名、删除、启停规划。删除题单保留历史，设置中可显式清理孤立题目。
- **训练**：开始、暂停、继续、结束不记录、四档评价、提示标记与笔记。Again=独立做不出；Hard=较多提示；Good=基本独立；Easy=快速熟练。Accepted 不代替评分。
- **计时**：可见页面发送心跳，超过 20 秒未更新不补算离开时间；5 分钟无键盘/点击活动自动暂停；单次最多 2 小时。仅记录活动发生，不读取按键内容或代码。跨天训练统一归入评分完成日期。
- **分析**：今日新题/复习次数、累计不同题数、今日/累计有效秒数、12 周/全年日历、按日详情和历史。任务推荐不会染色。
- **设置**：时间、新题上限、偏好、保持率、时区、积压减新题开关。恢复模式默认暂停新题，明确偏新题时最多分配 30% 时间给新题。

## 权限与导入

默认权限只有 `sidePanel`、`storage`、`scripting`；没有 `<all_urls>`。主动启用集成或读取公开题单时才申请 `https://leetcode.cn/*`。启用后刷新原有题目页面；快捷浮层可关闭，不修改编辑器。停用后刷新页面移除入口。

URL 导入只读取主动打开页面的公开 DOM/公开内嵌元数据；不调用私有 GraphQL，不绕过登录、验证、付费或反爬。官方题单必须实际元数据与核验清单一致才标完整；通用页面完整性未确认时需明确确认部分导入；无真实题目则失败并回退粘贴。此次官方 Hot100 的 100 题预览通过，用户公开题单 q3iOID0B 匿名读取未得到题目，不保证任意公开题单可自动解析。

粘贴支持编号、完整题目链接及 Markdown。已核验编号匹配元数据；未核验编号要求补充链接，不猜题名。未知链接显示“待补全标题”，可个人编辑。先预览识别/重复/未识别，再确认合并或另存新名。

## 备份和 v1 迁移

设置 → 导出 JSON。备份包含 `schemaVersion: 1`、`sourceApp: RecallCode-v2`、导出时间、题目、题单、共享进度、FSRS 状态、评分事件、会话、暂缓、设置；schemaVersion 是数据格式版本。没有账号、Cookie 或令牌。

恢复先校验并预览；默认合并，相同主键保留本机进度/事件，题单成员取并集，设置采用备份值。事务失败全部回滚，重复恢复不叠加时长；导入的运行会话先暂停。

v1：自行在原网站登录并导出，再到本插件选择 JSON。源导出缺少完整题单关系且最多 500 条最近历史，迁移会明确提示。题目归入“历史导入题目”，保留笔记和旧评分参考，待真实初评后才建 FSRS。邮箱等身份信息不进入新备份。插件不访问线上数据库。

卸载、清理扩展数据或更换扩展 ID 可能丢失本机记录，请定期备份。

## 架构与来源

`src/storage/` 是 Dexie schema v1、事务、会话、备份/迁移。题单成员嵌入 StudyList；progress 按题目 key 全局共享。偏好镜像到 Chrome Storage，业务读取以 IndexedDB 为准。

`src/domain/` 独立封装 FSRS、Daily Planner、规范化和来源校验。已知题 key 为 `leetcode:cn:<frontendId>`；v1 `lc:<number>` 显式迁移；未知 slug 使用 `leetcode:slug:<slug>`。仅匹配已核验 slug，不按标题合并。

使用锁定的 `ts-fsrs@6.0.0`，实际 API `await DefaultScheduler()`；显式选择 FSRS-6、默认参数、保持率 .9，关闭 fuzz 和短时学习步骤，以每日算法训练为单位。卡片及原始 revlog 均保存。后台独立打包，避免 MV3 Worker 动态导入/DOM 预加载问题。

恢复阈值可传入：缺席 >=7 天或积压 >=10；测试覆盖 7/30/90 天与 15/30/60 分钟，不批量改写 due。

`src/data/` 来自官方公开学习计划页面实际内嵌元数据，保存来源和核验时间，仅含最小题目信息，没有题面或题解。三份数据精确为 100/150/50。`node tests/verify-presets.mjs` 可重新核验，页面变化或网络问题会明确失败。

详情与截图见 `../docs/RECALLCODE_V2_VALIDATION.md`。可选的撤销评分和通知未实现，无云同步；剩余人工验收完成前不能宣称全量通过。

原 `app/` 是独立的 v1 网站，不作为插件运行依赖。不得将 v1 账号、Cookie 或身份资料用作插件身份，不得操作线上数据库。
